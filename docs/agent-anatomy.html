Anatomy of an agent

Terms such as harness, agent, tool, skill, sub agent, orchestration, meta-harness, and Claude Code describe three views: what an agent contains, how agents scale within a session, and how whole sessions are managed from outside.

Core concepts

Harness
The runtime around the model. It builds context, runs the loop, executes tool calls, enforces permissions, and manages the context window. In practice: Claude Code is a harness; the Agent SDK lets you build your own.
Claude Code
A harness product with a terminal UI, built-in tools, permission modes, plugins, and MCP support. In your setup: the thing that reads your marketplace and loads its plugins.
Agent
The model, harness, tools, context, and instructions running toward a goal. It is the whole system, not a separate component. In practice: every Claude Code session is one agent.
Tools and scripts
How the agent acts: built-ins (Read, Edit, Bash), MCP servers for external systems, and scripts invoked through Bash. Each call's result returns to the context. Rule of thumb: tools act outside the context; their results return to it.
Skill
Packaged instructions in a SKILL.md, loaded into context on demand. A skill does not execute, but it can direct the model to run scripts. In your setup: every non-bundle acme plugin ships a skill such as ping.
Sub agent
A fresh agent spawned through a tool call, with a separate context, its own tool set, and often its own system prompt. It works elsewhere and returns a report. In practice: the Agent tool; custom types in agents/*.md, which plugins can ship.
Orchestration
Coordinating multiple agents: fan out readers, pipeline find→verify, plan→work→review, or run adversarial checks. In practice: the Agent tool used in parallel, workflow scripts, or orchestrator agents such as elixir-phoenix:parallel-reviewer.
Meta-harness
An external app that spawns and manages whole harness sessions, adding features such as browser UI, parallel sessions per worktree, review queues, and runtime integration. In practice: Tidewave, session managers, and agent boards drive Claude Code through headless mode or the Agent SDK.

Distinctions that do the work

Skill vs tool

A skill tells the model how; a tool lets it act. Skills enter the context (amber), while tools are called from it (teal).

Agent vs harness

The harness is the runtime; the agent is the running system, including the model.

Skill vs sub agent

Both package expertise. A skill keeps work in the current context; a sub agent works in a separate context and returns a conclusion.

Sub agent vs orchestration

A sub agent is one delegate; orchestration is the coordination pattern across delegates.

Where this repo fits

The marketplace in this acme repo distributes plugins. Plugins carry skills, sub agent definitions, hooks, and MCP or Language Server Protocol (LSP) configuration. Claude Code installs and loads them into sessions. Each session is an agent that can orchestrate more agents.
